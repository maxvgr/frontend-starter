# Frontend Starter

Стартовый шаблон для адаптивной многостраничной вёрстки.

Сборка предназначена для быстрого старта обычных frontend-проектов без привязки к конкретному дизайну или CMS.
В шаблоне остаются универсальные инструменты, которые могут пригодиться в большинстве проектов, а проектная логика добавляется отдельно.

## Происхождение

Frontend Starter основан на сборке
[`acr0matic/frontend-reborn`](https://github.com/acr0matic/frontend-reborn)
и развивается как отдельный шаблон.

Исходный проект указывает лицензию MIT в `package.json`.

## Требования

Необходимо установить:

- актуальную LTS-версию Node.js;
- Corepack.

Версия Yarn зафиксирована в проекте:

```text
yarn@4.18.0
```

При необходимости Corepack можно включить командой:

```bash
corepack enable
```

## Установка

Клонировать репозиторий:

```bash
git clone https://github.com/maxvgr/frontend-starter.git
```

Перейти в каталог проекта:

```bash
cd frontend-starter
```

Установить зависимости:

```bash
yarn install
```

## Разработка

Запуск dev-сервера:

```bash
yarn dev
```

Webpack Dev Server автоматически откроет проект в браузере и будет отслеживать изменения файлов.

Production-сборка:

```bash
yarn build
```

Результат собирается в каталог:

```text
dist/
```

## Основные команды

```bash
yarn dev
```

Запуск проекта в режиме разработки.

```bash
yarn build
```

Production-сборка.

```bash
yarn build_wp
```

Production-сборка с дополнительной обработкой файлов для WordPress через Gulp.

```bash
yarn deploy
```

Загрузка содержимого `dist/` на сервер через FTP.

## HTML

Страницы находятся непосредственно в:

```text
src/*.html
```

Для подключения HTML-фрагментов используется PostHTML:

```html
<include src="layout/header.html"></include>
```

Для inline SVG:

```html
<inline src="assets/images/icon.svg"></inline>
```

Повторяющиеся элементы и шаблоны рекомендуется выносить в:

```text
src/layout/
```

## SCSS

Основные настройки проекта находятся в:

```text
src/scss/settings/
```

Здесь задаются:

- шрифты;
- цвета;
- типографика;
- брейкпоинты;
- контейнеры;
- глобальные CSS-переменные.

Переиспользуемые компоненты находятся в:

```text
src/scss/layout/components/
```

Крупные блоки:

```text
src/scss/layout/partials/
```

Стили конкретных страниц:

```text
src/scss/layout/pages/
```

Для адаптива используются централизованные брейкпоинты и миксин `mq()`.

Не рекомендуется добавлять произвольные media queries, если нужный брейкпоинт уже существует в проекте.

## JavaScript

Основной JS находится в:

```text
src/js/
```

Структура:

```text
component/   переиспользуемые компоненты
global/      глобальная инициализация и настройки
layout/      логика элементов layout
libs/        дополнительные библиотеки
utils/       вспомогательные функции
```

Компоненты подключаются через:

```text
src/js/global/init.js
```

Необязательные компоненты могут присутствовать в starter, но быть отключены по умолчанию.

## Готовые компоненты

В starter предусмотрена базовая логика для:

- модальных окон;
- аккордеонов;
- табов;
- галерей;
- Swiper-слайдеров;
- форм и клиентской валидации;
- масок полей;
- lazy loading;
- cookie notice;
- управления количеством;
- видео.

Конкретная разметка и дизайн компонентов адаптируются под проект.

## Формы

Базовая логика форм находится в:

```text
src/js/component/form.js
```

Форма с кастомной валидацией:

```html
<form class="form form-custom" data-validation>
```

Поля для проверки отмечаются:

```html
data-validate
```

После успешной отправки может использоваться событие:

```js
formSuccess
```

Подробности интеграции с backend находятся в:

```text
BACKEND.md
```

## Cookie notice

В starter есть лёгкий cookie-компонент на базе `js-cookie`.

Он не является полноценной CMP-системой и предназначен как базовая заготовка для проектов, где требуется простое уведомление о cookie.

Компонент по умолчанию можно оставить отключённым и включать только при необходимости.

## Галерея

Галерея поддерживает стандартное поведение с превью.

Для проектов, где на мобильных устройствах нужен свайп основной галереи, предусмотрен отдельный модификатор:

```html
b-gallery--mobile-swipe
```

Таким образом мобильный свайп не меняет поведение обычной галереи без явного включения.

## Табы

Компонент табов поддерживает определение начальной активной вкладки через класс:

```html
is-active
```

Если активная вкладка не указана, используется первая.

## Дата сборки

При запуске:

```bash
yarn dev
```

или:

```bash
yarn build
```

Webpack формирует текущую дату сборки.

Она доступна в HTML через переменную:

```html
{{ buildDate }}
```

Дата отражает момент сборки проекта, а не дату последнего Git-коммита.

## Деплой

Для FTP-деплоя используется:

```bash
yarn deploy
```

Настройки подключения передаются через `.env`.

Пример:

```text
FTP_HOST=
FTP_USER=
FTP_PASSWORD=
FTP_SECURE=
```

Секреты и реальные данные доступа не должны попадать в Git.

## WordPress

Для подготовки файлов под WordPress используется:

```bash
yarn build_wp
```

Команда выполняет обычную production-сборку и дополнительные Gulp-задачи.

Настройки WordPress-обработки могут потребовать адаптации под конкретный проект.

## Backend-интеграция

Правила передачи вёрстки backend-разработчику описаны отдельно:

```text
BACKEND.md
```

Основной принцип: backend-интеграция не должна ломать CSS-классы, `data-*` атрибуты и структуру интерактивных компонентов.

## Правила работы со starter

Starter должен оставаться универсальным.

В основную сборку имеет смысл добавлять только решения, которые:

- используются или потенциально полезны в большинстве проектов;
- не содержат бизнес-логику конкретного сайта;
- не привязаны к конкретному дизайну;
- не меняют поведение проекта без явного подключения;
- упрощают повторяющуюся frontend-работу.

Специфичные секции, карточки, цвета, контент и проектные компоненты остаются внутри конкретного проекта.

## Проверка перед коммитом

Минимальная проверка:

```bash
yarn build
```

Production-сборка должна завершаться без ошибок ESLint, Stylelint и Webpack.

## Коммиты

Используется простой формат:

```text
type: описание
```

Основные типы:

```text
feat: новая функциональность
fix: исправление ошибки
refactor: изменение структуры без изменения поведения
docs: документация
chore: техническое обслуживание
```

Примеры:

```text
feat: добавить мобильный свайп галереи
fix: исправить валидацию необязательного поля
docs: обновить README
chore: обновить зависимости
```
